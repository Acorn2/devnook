# 端口又被占了，我做了个开源的 macOS 项目与服务管理工具 DevNook

大家好，我是赫什，平时会同时开发几个项目，也会让 Codex 帮忙启动前后端。

麻烦的是，我有时并不清楚哪些服务还在运行。等到自己再敲启动命令，看到端口被占用，才发现旧服务还在。查到 PID，还得弄清楚它属于哪个项目、能不能停，再回去继续开发。

于是做了 DevNook，把项目、开发服务和端口放在一起管理。它运行在 macOS 上，用 Tauri + Rust + React 实现，MIT 开源。

官网：[DevNook](https://acorn2.github.io/devnook/)

源码：[GitHub](https://github.com/Acorn2/devnook)

![DevNook 项目列表，使用演示数据](https://acorn2.github.io/devnook/assets/projects-dark-zh.png)

**找到项目，再看它有哪些服务**

选择代码目录，预览扫描结果后导入。项目可以搜索、分类、收藏，也可以用自己常用的 VS Code、Cursor 或 JetBrains IDE 打开。

端口页能看实际 TCP 监听、进程命令、工作目录和项目归属。终端、IDE 或 AI 助手启动的外部监听也会显示。能依据工作目录确认归属的进程，会关联到已导入项目；也支持手动确认归属。无法核验身份或归属的进程保持只读。

服务列表优先展示项目名，进入项目后再区分里面的服务。这是我自己使用中反复调整的地方：看到一排 node，还是得重新认目录；先看到项目名，才容易知道自己在看什么。

**保存启动方式，集中看状态和日志**

启动命令保存为服务配置，确认后执行，下次开发时接着用。状态、实际端口和日志都能在服务详情里看，不必再找当时的终端窗口。

多个已登记的服务可以组成启动方案，等待依赖就绪后再启动下游，例如数据库 → API → 前端。关闭主窗口后，已经启动的托管服务继续运行，菜单栏可以查看状态、进入详情或正常停止托管服务。

外部服务不会被自动接管。切换为托管需要单独确认，会先正常停止旧实例，再启动新实例，中间会有短暂中断。

**让 AI 继续使用同一份配置**

我还会用 Codex 改代码、查日志，所以也提供了 CLI 和可选的 MCP 接入。桌面和 AI 助手可以查询同一份状态、读取日志，复用已经保存的服务配置。

MCP 默认只读，控制服务需要显式授权，并遵循对应的确认流程。接入需要自己配置，DevNook 不会自动修改 AI 客户端；只用桌面功能无需配置 MCP。

**试用前说清楚几个限制**

- 支持 macOS 12+，提供 Apple Silicon 和 Intel 安装包；Windows / Linux 暂无安装包。
- 当前安装包是 ad-hoc 签名，尚未完成 Developer ID 签名和 Apple 公证，首次打开可能被系统阻止。发布页有校验文件及打开说明。
- IDEA Run Configuration 插件还没做，当前支持打开 IDE 和配置命令行服务，不会迁移原有的 IDE 调试会话。
- 扫描、导入和保存配置不会执行项目命令，扫描不读取 `.env`。未发现 TCP 监听也不代表项目一定停止。
