# DevNook 使用指南

[返回中文首页](../README.md) · [English README](../README.en.md)

本指南介绍项目发现、编辑器选择、服务管理、端口排查、语言设置和数据边界。首次运行与开发命令见首页；启动方案及 CLI / MCP 的详细配置见 [Phase 3 使用说明](PHASE-3.md)。

## 使用

1. 点击“扫描项目”，选择目录，默认按清单与模块声明发现 JavaScript/TypeScript、Java/Kotlin、Python、Rust、Go、.NET、PHP、Ruby、Dart/Flutter、Swift/Xcode、C/C++ 工程。识别项目后只继续声明模块、常见前后端目录及有限浅探，不递归普通源码、文档、素材和隐藏目录（`.tools` 除外）。明确声明的安全路径和已导入组件会定点复查。非常规布局可在高级设置启用“深度补扫非标准目录”（1–12 层），或直接选择具体目录；两种模式都不执行脚本、安装依赖、读取 `.env` 或跟随符号链接。
2. 按名称、路径、技术栈或内部组件搜索候选，搜索保留选择；“全选当前结果”只操作可见未导入项目。同一仓库/工作区的前后端作为一个项目的服务候选展示，独立嵌套仓库可单独选择。导入后点击项目直接查看前后端服务。明确识别出的启动命令会自动填入；点击“启动…”后确认执行。无法识别时只需补充启动命令，高级参数按需展开。扫描和导入不会自动创建或启动服务。
   同一规范路径只保留一个档案；已有档案可勾选更新线索，保留 ID 与偏好，已有独立档案不会自动合并或删除。
3. 项目默认使用紧凑列表，也可切换卡片 / 表格；选择“按分类分组”后可折叠各组，未分类项目放在最后。视图、分组、折叠与排序偏好在本机记住。搜索、按技术栈 / 分类 / 端口状态筛选、收藏项目；一键打开默认开发应用，或用下拉选择临时打开方式、点击图钉设置此项目默认。打开档案可编辑默认应用、名称，选择已有分类或新建分类，也可设为未分类；可打开 Finder/Terminal。点击“批量分类”可逐项勾选、全选当前筛选结果或选择整个分类组，再统一选择已有分类、新建分类或设为未分类。更换搜索 / 筛选会清空勾选；保存遇错停止，已完成的更改保留，其余项目可核对后重试。移除档案不会删除源码。
4. “端口管理”自动刷新 TCP IPv4/IPv6 绑定。选择端口按需读取命令、PID/PPID/PGID、可执行文件、cwd、父进程链和启动时间。
5. cwd 明确位于项目内时自动关联；命令匹配只作建议。可人工确认本次进程的项目归属，修正绑定启动身份，不绑定永久 PID。
6. 只有同用户、身份和归属可核验的非保护进程允许停止。输入 PID 确认后只发 SIGTERM；不自动强杀，不终止外部进程组。

扫描聚焦可在本机运行的服务与开发服务器：明确的纯 iOS / Xcode、Android、Flutter 客户端，以及 JavaFX / Compose、.NET GUI / MAUI、Electron / Tauri、Rust / Go / Python GUI、Qt 和 Unity / Unreal / Godot 客户端，不再单独出现在新候选中。默认与深度补扫使用相同规则。混合仓库中的后端、Swift 服务端、Expo / React Native 开发服务器和明确的 Web 服务脚本仍保留；Electron 工程有独立 Vite 脚本时只建议该脚本，不建议启动客户端。普通 CLI / worker 不要求监听端口，相关共享库保留为组件。已有档案、服务配置和运行不会因规则变化被删除或停止。自定义启动器与 headless 游戏服务无法静态确定时需手动配置，详细范围见[服务与客户端扫描边界](service-eligibility-plan.md)。

项目列表的“端口状态”可选择全部、检测到服务监听、未检测到服务监听，并与搜索、技术栈、分类及收藏组合。仅统计 Core 已识别的服务监听，工具自身和用途不明的端口不影响项目状态；未检测到不等于项目已停止，读取失败时显示状态不可用。侧栏不再单列两种监听状态或“工作区组”，启动方案从服务管理进入。

端口管理的侧栏入口不显示数量。页内按“同一 PID + 端口计 1 项”统计 TCP 监听项，合并 IPv4 / IPv6 与多个地址，包含系统和开发工具。搜索、项目与地址族筛选可叠加“更多筛选”中的运行时、进程类型和启动来源，显示“当前结果 X / 总数 N”。运行时仅按进程名分组，不根据项目技术栈猜测原生程序语言；来源只区分 Core 核验的 DevNook 托管和外部发现，不推断具体 IDE / AI 工具。总数始终来自完整的成功快照；更新时间表示最近一次成功读取。刷新中保留上次快照并注明状态，读取失败或未连接时数量显示“—”；成功读取的空快照显示 0。

服务列表与详情直接显示实际 TCP 监听端口、地址族和 PID，预期端口仍单独保留在运行详情中。项目服务页的“外部启动的服务”只汇总已关联项目且具有服务入口证据的监听进程，例如终端、IDE、Codex、WorkBuddy 启动的 Node / Python 后端、Vite / Next / Expo 开发服务器、Java 应用等。工具自身的端口及用途不明的监听仅保留在端口管理，不单独增加工具分组；每个 PID 独立识别，不因父进程是开发工具而隐藏子服务。导入后立即重新读取归属和入口分类，无需重启原进程；多个端口按 PID 合并。点击“关联服务…”可核对已识别服务的项目归属；其余进程仍可在端口管理确认归属。确认只绑定本次进程身份，不改变用途分类、不创建或接管服务。入口识别采用只读静态规则，自定义启动器或无法解析的命令可能只在端口管理显示。

服务配置、未保存的启动建议与已关联外部服务旁均有项目星标，点击可收藏或取消收藏所属项目。同一项目的所有条目及项目库“已收藏”同步；点击星标保留当前选中服务和列表顺序。保存失败会显示错误并保留原状态，可再次点击重试；无法找到项目记录时不显示星标。

外部服务详情可直接“停止外部服务”：核验资格、预览并输入 PID 确认后，仅发送 SIGTERM，不自动强杀。也可“配置为 DevNook 服务”：从项目清单提供可编辑建议，环境变量和启动条件需自行核对；保存新配置不会停止或启动服务，随后可选择仅保存，或再次输入 PID 确认切换。切换先检查新配置、依赖与端口，再正常停止旧 PID；旧实例退出且相关端口释放后才由 DevNook 启动。超时、身份 / 配置变化或占用会中止，配置保留；不会自动恢复旧实例、接管旧进程组、复制旧环境 / 历史日志或延续 IDEA 调试会话。这些功能从桌面操作，MCP 不开放。

开发应用由 Core 从 macOS 系统登记、`/Applications`、`~/Applications` 和系统 Terminal 目录只读发现；识别 VS Code、Cursor、Windsurf、Trae、Qoder、Zed、Sublime Text、JetBrains 系列、Xcode 和 Android Studio。菜单只列出实际存在且清单、可执行文件有效的应用，按项目线索推荐；多版本通过版本和路径区分。Finder / Terminal 位于独立分组。可“选择其他应用…”手动指定 `.app`；通过校验后会立即记住，后续刷新和重启仍在应用列表中，不必设为项目默认。保存设置不会清除已记住的应用。应用暂不可用时保留记录，恢复到原路径后自动出现；也可刷新列表。发现、记住和设置默认不会启动应用；卡片菜单的选择操作仍会显式请求打开。菜单采用紧凑列表，版本信息仅在同名应用或悬停提示中展示，下方可容纳短列表时优先下拉，否则贴着按钮上翻，列表内部滚动。

新导入项目（包括 Java）继承设置中的全局默认开发应用；项目单独指定后优先使用自己的选择，更改全局默认不改写已有项目。临时选择不会修改偏好。应用移除后保留已保存的选择并提示重新选择，打开失败显示实际错误。旧 IDEA / VS Code / Cursor 偏好和自定义路径仍兼容，高级路径设置默认折叠。

界面支持浅色和暗色：顶栏可一键切换，设置页“界面外观”可预览选择，立即生效并在当前设备自动记住。首次打开使用系统配色，之后尊重已选主题；主题切换不依赖 Core 连接，不需要点击“保存设置”。两种主题共用蓝青操作色、分层表面及独立的状态色，菜单、弹窗、日志、端口与服务页面同步切换。配色与交互规则见 [DESIGN.md](../DESIGN.md)。

界面提供简体中文和 English。首次启动按 macOS 首选语言选择：中文（含地区和脚本变体）使用中文，其他语言统一使用英文，不根据次选语言选择中文。在“设置 → 界面语言”（Settings → Language）中可即时切换，应用自动记住手动选择，无需点击“保存设置”，重开后优先使用该选择。语言切换保留当前表单；存储不可用时仍切换本次界面并提示无法保存。项目名、分类名、路径、命令、原始日志和底层诊断数据保持原文；语言不改变项目或服务配置。

## 菜单栏快捷面板

点击 macOS 菜单栏 N 图标查看运行中、异常及收藏项目的服务。单服务项目直接一行，多服务按项目分组。实际端口与状态同排，点击名称进入详情；托管服务可正常停止，启动 / 重启会转到主窗口确认。外部与未知实例没有快捷停止。

列表超高时只滚动服务区，底部入口固定，上下箭头提示剩余内容。超过 12 条自动显示搜索，也可按 ⌘F，按项目、服务或实际端口查找；方向键选择、Enter 进入详情、Escape 收起。同次展开的顺序、高度与滚动位置保持稳定，失效条目立即禁用，下次展开重算。

菜单栏浏览器按钮仅显示近期在详情确认、且当前监听 / 进程身份仍匹配的单一网页入口；API / 未知 / 多入口进入详情读取或选择。展开面板不会批量探测端口。关闭主窗口保留菜单栏，可从 Dock 或面板恢复；“退出 DevNook”只退出 GUI，服务继续运行。升级前正常退出旧 GUI，避免同时出现多个图标。

## 数据与边界

服务管理包含“服务列表”和“启动方案”：服务列表管理单个服务；启动方案组合多个服务，审阅确认后按依赖顺序启动、等候 READY，并在失败时只回滚本次创建的实例。启动方案沿用原有工作区数据和 CLI / MCP 接口。

终端命令与可选 AI 接入位于“设置 → 高级选项”，不单独占用侧栏。CLI 可在终端或脚本中查询服务、读取日志和启动已保存的方案，与桌面共享配置和运行记录。需要 AI 编程助手复用这些配置、并在桌面管理它启动的服务时，可展开“AI 助手接入（MCP，可选）”配置客户端；日常桌面与 CLI 使用无需接入 MCP。MCP 默认只读，查询无需控制授权；启停等控制操作需额外授权，并沿用各操作的确认流程。创建授权不会自动连接客户端或启动服务，详见 [Phase 3 使用说明](PHASE-3.md)。

Phase 2 服务使用与数据模型见 [服务托管说明](PHASE-2.md)。服务管理入口位于左侧导航和项目卡片，支持配置、启动确认、正常停止、独立确认强制停止、重启、历史运行、实时日志与搜索。

普通环境变量保存在 SQLite；敏感值进入 macOS Keychain，按配置版本隔离引用。保存配置不会执行命令。默认使用 executable + args，需要登录 Shell、nvm 或组合命令时显式开启 Shell Mode。

就绪支持 PROCESS、PORT、HTTP、LOG_PHRASE，端口与 HTTP 必须属于本次进程组。HTTP 仅访问 loopback HTTP 2xx，不跟随重定向。未就绪超时会请求正常停止；停止宽限过后才允许独立确认强杀。重启必须等待原组退出。

未活动服务的详情会列出当前快照中占用相同预期端口的进程：端口、PID、命令、工作目录和项目。可跳转端口管理查看进程，或查看已核验的托管服务；停止继续使用原有入口和安全确认。启动阻断后的占用已消失时明确区分历史错误与当前快照，不自动停止占用者或重试启动。

托管和外部服务详情均可“打开浏览器”：单个实际监听端口默认用 HTTP 打开站点首页，多端口先选择地址；旁边的“地址”菜单也可选择 HTTPS 或重新读取。没有监听、快照不可用或服务已停止时禁用。打开前再次核对当前监听与进程身份，不使用预期端口、日志链接或健康检查路径代替站点地址，也不会自动启动 / 停止 / 重启服务。TCP 监听本身不代表该端口支持 HTTP。

- 数据库：`~/Library/Application Support/com.devnook.desktop/devnook.db`，SQLite WAL，记录项目、设置、人工归属和操作审计。
- 监听来自 `lsof`，进程来自 `ps` / `lsof` / macOS libproc；无须 root。权限不足时字段显示不可访问。
- “未发现监听”仅描述 TCP 快照，不能证明项目中没有 Worker 或其他后台任务。
- Phase 2 区分 DevNook 托管与外部发现；托管归属依据 runner 微秒启动身份、UID 和 PGID，不能仅通过端口认领。外部进程不提供自动重启，IDE 托管需等待插件阶段。
- Core 与独立 runner 使用同一 Rust Core。GUI 关闭后服务和日志继续运行，Core 重启后核验恢复；无活动服务且客户端闲置 5 分钟后可退出，未安装 LaunchAgent。
- UDS 位于应用数据目录 core.sock，目录 0700、socket 0600，验证同用户；没有 HTTP 管理端口。日志位于 logs/services/，单文件 0600，脱敏后限量落盘，超长行整行省略。
- SQLite v3 升级 v2 前保留 devnook.phase2-backup.db，增加工作区与授权/审计；v2 首次升级 v1 前保留 devnook.phase1-backup.db，增加服务配置和独立运行历史，不覆盖项目档案。配置移除为归档，保留历史/日志；有活动服务时阻止移除项目。
- 不读取项目 .env；默认仅继承必要用户、语言、临时目录和工具路径。Shell Mode 会读取用户 Shell 环境，需核对启动脚本；不要向服务输出中写入未登记或变换编码后的秘密。
- 无法核验的 orphan 组标为 UNKNOWN，不发送信号或重复启动；主动逃离原进程组的程序不属于可安全托管范围。
- Phase 2 测试需要 Node.js、Python 3 和 JDK，测试密钥使用内存存储。Intel、真实 Keychain 交互及具体 Maven/Gradle 项目仍需各自环境验证。

## 升级与连接故障

当前 Core UDS 协议为 v10，SQLite 仍为 v3。升级前退出旧桌面及 CLI/MCP 客户端，等待旧 Core 正常退出后再打开新版；无活动服务时闲置约 5 分钟退出。有托管服务时请先按既有确认流程正常停止。应用不会自动终止不兼容的旧 Core。CLI `project scan` 和 MCP `preview_project_scan` 的 `depth=0` 表示特征扫描，`1–12` 表示受限递归补扫。进度分别显示检查目录数和枚举条目数；100000 条目、120 秒、5000 原始候选和自动 32 层保护仍保留，模块路径展开同样受预算和所选根范围约束。

如果旧 Core 仍在运行，新版窗口会打开并显示连接原因，不会因协议不兼容闪退。请在旧版中正常停止托管服务，再退出旧桌面与 CLI/MCP 客户端；旧后台正常退出后，点击新版提示中的“重新连接”即可读取已有项目，无须重启窗口。主题与设置页面仍可打开；依赖 Core 的操作在连接成功前禁用。不会自动关闭旧 Core 或清空项目库。

模块声明覆盖 npm/Yarn workspaces、pnpm packages / 排除、Cargo workspace / path 依赖、uv workspace、Maven modules、Gradle 字面量 include / includeBuild / file 字面量 projectDir 映射、go.work use、.NET solution / ProjectReference、Dart workspace、CMake / Meson 字面量子目录及 .gitmodules path。动态脚本不求值，不能静态展开时会提示可能不完整。发现项目或框架依赖不保证能确定启动命令；未支持的语法、无清单脚本及任意深层的未声明嵌套仓库需要补扫或手动填写入口。详细范围见[扫描设计与类型覆盖](scanner-features-plan.md)。

项目内的启动建议来自当前磁盘清单：Node 的 dev/start/serve 脚本与项目内包管理器声明/锁文件、Spring Boot 的 Maven/Gradle 任务、Gradle application 与 Rust src/main.rs。建议未经运行验证；不明确的入口留空供用户填写。根目录聚合脚本列在“其他启动方式”，避免与前后端重复运行。已有服务配置保持原样，不会被建议覆盖。单行启动命令默认解析为 executable + args；组合命令、变量展开须在高级设置显式启用 Shell 模式。
