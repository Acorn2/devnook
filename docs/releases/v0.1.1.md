# DevNook v0.1.1

本次更新补齐外部服务切换托管、AI 交接和服务入口展示，修复旧 Core 的配置预览兼容及自定义 Node 服务命令自动填充。

## 更新内容

- **已有配置切换托管**：选择已保存的服务配置与当前外部实例，先查看独立预览；PID 只读展示，点击“停止旧实例并以托管方式重启”才执行。Core 保留进程身份、配置版本、依赖及端口核验。
- **清楚区分配置与运行**：没有运行记录显示“未启动”；外部监听单独展示。保存配置与普通启动不会自动停止外部服务，端口冲突仍阻断启动。
- **AI 继续管理**：从服务详情复制当前服务的 CLI / MCP 交接指引，并前往设置完成接入。MCP 默认只读，控制服务需范围授权与对应确认；不会自动修改 AI 客户端配置，结束聊天不默认停止服务。
- **可靠的配置建议**：兼容缺少配置预览接口的旧 v10 Core；对有清单与入口证据的 Node 自定义脚本自动填充启动命令，不复制旧环境或重放观察到的命令。
- **服务与网页入口**：全局优先展示项目名，项目内优先展示服务名；从核验过的实际监听选择 HTTP / HTTPS 地址。自定义网页服务器可直接打开，明确无根页面的 API 展示监听，未知入口仍保留尝试打开。
- **文档与官网**：更新中英文指引及演示截图，区分服务配置、外部运行、网页入口与日志。

## 安装与升级

macOS 12+，按芯片选择下方 DMG，打开后拖入 Applications。已有配置和运行仍由本机 Core / runner 维护；升级 GUI 不会自动退出旧 Core 或停止服务。若旧后台缺少切换能力，界面会提示限制，不绕过核验。

切换托管会短暂中断被选中的服务：正常停止旧 PID，等待退出与相关端口释放，再启动新的托管实例。失败保留配置，不自动强杀或恢复旧实例；旧进程环境、历史日志及 IDE 调试会话不迁移。请先让原 Codex / IDE 会话改用 DevNook CLI / MCP，避免重复拉起。

两个包均为 **ad-hoc 签名，未完成 Developer ID 签名或 Apple 公证**。macOS 可能阻止首次打开；核对来源与 SHA-256 后，可参阅 [Apple 的应用安全打开说明](https://support.apple.com/en-us/102445)。不提供 Windows / Linux 安装包。

## English

This release completes external-to-managed service handoff, AI handoff instructions, and clearer service and browser entry presentation.

- Reuse a saved configuration, select the external instance, and review a separate preview. The PID is read-only. Only **Stop old instance and restart under DevNook** executes the switch; Core still checks identity, configuration revisions, dependencies, and ports.
- Distinguish unstarted configurations from stopped runs and external listeners. Saving configuration and ordinary start never stop external instances automatically; port conflicts still block startup.
- Copy service-specific CLI / MCP instructions so an AI assistant can continue using the same configuration. MCP is read-only by default; control requires scoped authorization and confirmation. Client setup is explicit, and ending a chat does not stop the service automatically.
- Preview configuration with older v10 Core versions, and autofill custom Node scripts when supported by manifest and entry evidence. No environment copying or replaying observed process commands.
- Display project names globally and service names within projects. Custom web servers get a verified HTTP entry; API roots without a page show listeners, while unknown entries retain a browser attempt.

Choose the DMG for your Mac and drag DevNook into Applications. Both builds target macOS 12+ and are **ad-hoc signed, without Developer ID signing or Apple notarization**. See [Apple’s guidance](https://support.apple.com/en-us/102445) after checking the source and checksum.

Upgrading the GUI does not automatically terminate the existing Core or services. An explicitly confirmed switch briefly interrupts the selected service: gracefully stop the old PID, wait for exit and released ports, then start a managed instance. Failure keeps configuration without force-killing or automatically restoring the old instance. Existing environment, historical logs, and IDE debugging sessions do not migrate. Tell the original assistant or IDE session to use DevNook CLI / MCP to avoid duplicate starts.
